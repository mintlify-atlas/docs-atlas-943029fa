CREW uses API key authentication. Every request to the CREW API must include a valid API key in the `Authorization` header using the `Bearer` scheme. Keys are scoped to a single CREW account and inherit that account's permissions — meaning your API key can only access data and perform actions that your account is authorised to access.

## Obtaining an API Key

<Steps>
  <Step title="Log in to CREW">
    Visit [crew.app](https://crew.app) and sign in to your account.
  </Step>
  <Step title="Navigate to API Keys">
    Go to **Settings → Developer → API Keys** from your account dashboard.
  </Step>
  <Step title="Create a new key">
    Click **"New API Key"** to open the key creation dialog.
  </Step>
  <Step title="Name your key">
    Give the key a descriptive name that identifies where it will be used — for example, `"Production App"` or `"Casting Tool Integration"`. Select the appropriate scopes for your use case (see [Key Scopes](#key-scopes) below).
  </Step>
  <Step title="Copy and store your key">
    After creation, your key is displayed **once only**. Copy it immediately and store it securely — for example, in an environment variable or a secrets manager. You will not be able to view the key again after closing this dialog.
  </Step>
</Steps>

<Warning>
  API keys grant full account access within their scope. Never share keys publicly, commit them to source control, or embed them in client-side code.
</Warning>

## Making an Authenticated Request

Pass your API key as a `Bearer` token in the `Authorization` header of every request. The examples below all fetch the list of users from the CREW API.

<CodeGroup>
  ```bash cURL
  curl -X GET https://api.crew.app/v1/users \
    -H "Authorization: Bearer YOUR_API_KEY" \
    -H "Accept: application/json"
  ```

  ```javascript JavaScript
  const response = await fetch('https://api.crew.app/v1/users', {
    headers: {
      'Authorization': 'Bearer YOUR_API_KEY',
      'Accept': 'application/json'
    }
  });
  const data = await response.json();
  ```

  ```python Python
  import requests

  headers = {
      'Authorization': 'Bearer YOUR_API_KEY',
      'Accept': 'application/json'
  }
  response = requests.get('https://api.crew.app/v1/users', headers=headers)
  data = response.json()
  ```
</CodeGroup>

<Note>
  Replace `YOUR_API_KEY` with the actual key you generated in the CREW dashboard. Never hard-code keys directly in your source files — use environment variables instead (see [Security Best Practices](#security-best-practices)).
</Note>

## Key Scopes

When creating an API key you select one or more scopes that define what the key is permitted to do. Grant only the scopes your integration actually requires.

| Scope | Description |
|---|---|
| `read` | Read-only access to all public resources — users, listings, locations, equipment, and opportunities. |
| `write` | Create and update listings owned by the authenticated account. Requires `read`. |
| `messages` | Send and read messages on behalf of the authenticated account. |
| `admin` | Full access including account management operations. Restricted to verified applications only. |

<Tip>
  Scope keys to the minimum permissions your integration needs. A key used only to pull crew listings, for example, should have `read` only — this limits the blast radius if the key is ever compromised.
</Tip>

## Security Best Practices

Follow these guidelines to keep your API keys and your users' data safe:

- **Never expose keys client-side** — Do not include API keys in browser-side JavaScript, mobile app bundles, or any code that end users can inspect.
- **Keep keys out of source control** — Add key files to `.gitignore` and audit your repos with tools like `git-secrets` before pushing.
- **Use environment variables** — Store keys in environment variables and read them at runtime:
  ```bash
  export CREW_API_KEY="your_key_here"
  ```
- **Rotate compromised keys immediately** — If a key is exposed, revoke it straight away via **Settings → Developer → API Keys → Revoke**, then issue a replacement.
- **Apply minimum-privilege scopes** — Only grant the scopes your integration genuinely needs, and create separate keys for separate services.

## Error Response

If a request is made with a missing or invalid API key, the API returns a `401 Unauthorized` status with the following JSON body:

```json
{
  "error": {
    "code": "unauthorized",
    "message": "Invalid or missing API key."
  }
}
```

Check that your `Authorization` header is correctly formatted (`Bearer ` followed by your key with no extra whitespace) and that the key has not been revoked in your dashboard.
